## Что уже сделано правильно

Это не формальность — перечисленное закрывает те ошибки, на которых обычно и ломаются молодые мультиязычные сайты. Ломать это в ходе дальнейших работ нельзя.

| Проверка | Результат |
|---|---|
| Коды ответа | 133/133 → 200, ни одного 3xx/4xx/5xx внутри карты |
| Канонизация слеша | `/ru/faq` → 301 → `/ru/faq/`, корень → 301 → `/ru/` |
| Self-canonical | на всех страницах, всегда со слешем |
| hreflang | 7 языков + `x-default`, **взаимность 100 %**, ни одной односторонней ссылки |
| Коды локалей | `pt` → `pt-PT`, `br` → `pt-BR` — корректный BCP 47, не самодельные `br`/`pt` |
| hreflang в sitemap | продублирован `xhtml:link`-ами — второй канал сигнала |
| 404 | честный код 404 + `noindex, follow`, не soft-404 и не редирект на главную |
| Мусорные URL | `/wp-login.php`, `/zz/` → 404, а не 200 с русской главной |
| Скорость | 7.8 КБ HTML, 11.7 КБ CSS, ноль JS, ноль внешних доменов и шрифтов |
| Картинки | 7 из 7 с непустым `alt` |
| Дубли из query | `?utm_*` не порождают дублей: canonical строится из pathname |

## Находки

Severity: **Critical** — блокирует ранжирование как таковое; **High** — прямо ограничивает рост; **Medium** — заметная потеря; **Low** — гигиена.

### C1. Critical — объём материалов ниже порога ранжирования

| Метрика | Ve7as | Топ выдачи по тем же интентам |
|---|---|---|
| Медиана статьи | 236 слов | 1 500–3 000 слов |
| Минимум | 201 слово (`wagering-explained`) | — |
| Максимум | 421 слово | — |

Проверка планки по живой выдаче на запросе о вейджере: все восемь результатов первой страницы — материалы с формулой, таблицей вклада игр в отыгрыш, разобранными примерами, у половины — калькулятор. Статья `/ru/articles/wagering-explained/` — 201 слово, три подзаголовка, ни одной таблицы, ни одного числового примера, ни одной ссылки на источник.

**Следствие:** материал не конкурирует ни за один запрос, кроме сверхдлинного хвоста. Никакая техническая работа этого не компенсирует.

### C2. Critical — структурированная разметка отсутствует

На всех 133 страницах ровно один блок JSON-LD: `WebSite`. Отсутствуют:

| Тип | Где нужен | Что теряется |
|---|---|---|
| `Article` / `BlogPosting` | 9 статей × 7 локалей | `author`, `datePublished`, `dateModified`, `publisher` — базовые сигналы E-E-A-T для YMYL |
| `BreadcrumbList` | статьи (крошки уже есть в HTML, `src/pages/[lang]/articles/[slug].astro:88`) | цепочка навигации в сниппете |
| `FAQPage` | `/[lang]/faq/` — 208 слов готовых Q&A | расширенный сниппет и цитируемость в AI-ответах |
| `Organization` + `sameAs` | сквозная | привязка бренда к сущности; критично, см. M6 |

`dateModified` не выводится вообще — ни в разметке, ни в HTML. Для YMYL это один из немногих сигналов актуальности, который Google читает напрямую.

### H1. High — E-E-A-T не подтверждён ничем проверяемым

- **Ноль внешних ссылок** на всём сайте. Ни одной ссылки на регулятора (MGA, UKGC, Curaçao), сертификационную лабораторию (eCOGRA, GLI, iTech Labs), документацию провайдера. В YMYL-нише это означает отсутствие проверяемости утверждений.
- Автор выводится строкой `Автор: <имя>` (`src/pages/[lang]/articles/[slug].astro:98`), но: нет страницы автора, нет биографии, нет квалификации, нет `sameAs` на профили, нет `author` в разметке.
- Не заявлена редакционная политика: нет страницы «как мы проверяем факты», нет дат ревизии материалов.

Владелец проекта работает QA/SDET на платформе онлайн-казино — это ровно тот first-hand experience, ради которого Google и вводил букву E в E-E-A-T. Сейчас этот актив на сайте не выражен ни одним элементом.

### H2. High — требование ответственной игры выполнено частично

В футере есть строка «⚠️ Азартные игры предназначены только для лиц старше 18 лет. Играйте ответственно». Чего нет: **ссылки на профильную помощь** (GamCare, BeGambleAware, Gamblers Anonymous, локальные службы по каждой из 7 юрисдикций) и блока на уровне материала. Это нарушение собственного требования проекта и одновременно потеря сигнала доверия, который Google в gambling-нише читает явно.

### H3. High — слаг с невидимым символом U+2060

Статья «Как создаются игровые слоты» имеет слаг, оканчивающийся на U+2060 WORD JOINER:

```
/ru/articles/how-to-develop-igaming-slots%E2%81%A0/   → 200
/ru/articles/how-to-develop-igaming-slots/            → 404
```

Затронуто 7 URL (все локали). Дублей это не создаёт — в HTML стоит символьная форма, браузер кодирует её к тому же адресу, — но: URL нечитаем при копировании, любая внешняя ссылка, набранная руками или очищенная от невидимых символов чужим редактором, приведёт в 404, и `%E2%81%A0` попадёт в сниппет выдачи.

**Чинится только в Sanity Studio**, документ `36768224-a341-4ead-8201-839dd0d8affb`. У агента нет и не должно быть write-токена. После правки слага нужен 301 со старого адреса.

### H4. High — та же статья не переведена ни на одну локаль, кроме английской

`title` и `description` этой статьи отдаются **по-русски** в `br`, `de`, `es`, `fr`, `pt`. Механизм фолбэка работает как задумано, но результат — 5 страниц, где `<html lang="de">` соседствует с русским заголовком, и они объявлены через hreflang как немецкая, испанская, французская версии.

### H5. High — локали `pt` и `br` полностью дублируют друг друга

Совпадают дословно `title` и `description` на всех общих страницах (проверено: 6 пар полных дублей мета). Различий в текстах между португальской и бразильской версией нет. Формально hreflang их разводит, но при 9 материалах это удвоение индексного пространства без единого различающегося слова.

### M1. Medium — раздутая структура при пустом контенте

133 URL на 9 материалов. Ни одна локаль не имеет достаточной массы, чтобы получить авторитет. Это ровно тот риск, который зафиксирован в стратегических установках проекта, — теперь он подтверждён цифрами.

### M2. Medium — хаб-страницы рубрик пусты

| Рубрика | Слов | H2/H3 |
|---|---|---|
| `/ru/casino-slots/` | 134 | 0 |
| `/ru/poker-table-games/` | 102 | 0 |
| `/ru/lottery-esports/` | 96 | 0 |
| `/ru/sports-betting/` | 81 | 0 |

Хаб рубрики — главный кандидат на ранжирование по «категорийному» информационному запросу и опора топикального кластера. Сейчас это заголовок плюс список из двух карточек.

### M3. Medium — перелинковки между материалами нет

Все входящие ссылки на статью (8 шт.) приходят из индексных списков — главной и хаба рубрики. Контекстных ссылок из тела одного материала в другой: **0**. Топикальные кластеры не сформированы, вес не перераспределяется.

### M4. Medium — длины title и description вне диапазона

| Проблема | Страниц |
|---|---|
| `title` > 60 символов (обрезка в выдаче) | 53 / 133, максимум 96 |
| `description` < 70 символов | 21 (FAQ ≈ 40, privacy ≈ 50, terms ≈ 50) |
| `description` > 160 символов | 13 (about ≈ 165–194) |

Шаблон `Ve7as — <title>` на главной и `<title> — Ve7as` на прочих съедает 8 символов; на французской и бразильской главных заголовок доходит до 96 символов.

### M5. Medium — свежесть контента

`lastmod` статей: 9–20 июня 2026. На дату аудита — от 2 месяцев без единой правки. Кроме того, `lastmod` проставлен только у 63 URL из 133: статические страницы (`about`, `contacts`, `privacy`, `terms`, главные) идут без него.

### M6. Medium — брендовый запрос занят чужой сущностью

«VE7AS» — действующий позывной радиолюбителя из Британской Колумбии. Выдача по слову занята устойчивыми источниками: [qrz.com](https://www.qrz.com/db/VE7AS), [hamqth.com](https://www.hamqth.com/VE7AS), [qrzcq.com](https://www.qrzcq.com/call/VE7AS), плюс [аккаунт Ve7as на GitHub](https://github.com/Ve7as). Поиск `site:ve7as.com` не возвращает ни одной страницы домена.

Это значит: (а) брендовый трафик придётся отвоёвывать у сущности, существующей в вебе десятилетиями; (б) без `Organization` + `sameAs` и внешних упоминаний Google не имеет оснований связать домен с новой сущностью.

### L1. Low — заголовок `Cache-Control: private, max-age=60`

Отдаётся на всех страницах. Это осознанное решение (`src/middleware.ts`: HTML варьируется по стране через `blockedIn`), и для SEO оно безвредно — Googlebot не полагается на HTTP-кэш. Записано, чтобы при следующем аудите это не всплывало как «находка».

## Как повторить аудит

```bash
python3 -m venv .venv && .venv/bin/pip install httpx selectolax
curl -s https://ve7as.com/sitemap.xml | grep -o '<loc>[^<]*' | sed 's|<loc>https://ve7as.com||' | python3 -c "import sys,json;json.dump([l.strip() for l in sys.stdin],open('paths.json','w'))"
.venv/bin/python scripts/seo/crawl.py paths.json crawl.json
```
